Contexto, Alcance y Principios Fundamentales 1.1 Contexto y Alcance El presente documento establece la especificación técnica canónica y el estándar institucional para el Motor de Auditoría y Trazabilidad Transversal del CIIS OS. Define la arquitectura conceptual del modelo de eventos que servirá como estándar institucional único para la generación, captura, validación y verificación de auditorías en todo el ecosistema modular de CIIS OS. El alcance se delimita a la especificación arquitectónica abstracta, asegurando neutralidad tecnológica total. Su objetivo es actuar como un contrato inalterable que permite la interoperabilidad de componentes en diversos lenguajes de programación y motores de almacenamiento. 1.2 Principios Arquitectónicos Independencia y Agnosticismo Tecnológico: Neutralidad frente al backend, motor de persistencia (SQL, NoSQL, Time-Series) o runtime (PHP, Node.js, Python, Java, WebAssembly). JSON como Fuente Única de Verdad (Single Source of Truth): Todo evento se serializa e intercambia bajo una estructura JSON canónica y determinista. Alta Cohesión y Bajo Acoplamiento: Módulos emisores emiten estructuras JSON válidas sin requerir conocimiento de los receptores o almacenamiento. Evolución mediante Versionado de Esquema: Todo evento declara explícitamente su versión (schema_version), garantizando retrocompatibilidad a largo plazo. 1.3 Principios Fundamentales de Auditoría Inmutabilidad: Un evento registrado no puede ser modificado ni eliminado bajo ninguna circunstancia. Integridad: Todo evento incluye una huella criptográfica (hash) derivada de su contenido estandarizado. No Repudio: La combinación del modelo de actores, sello temporal y hash del evento impide la negación de una acción realizada. Evidencia Verificable: Soporta encadenamiento de hashes (Hash Chaining / Merkle Trees), permitiendo auditar matemáticamente si la secuencia de registros ha sido alterada. Trazabilidad Completa: Permite reconstruir el estado de cualquier objeto auditable mediante la correlación histórica de eventos. Auditoría Determinista: Ante los mismos datos de entrada y contexto, la serialización canónica genera exactamente la misma huella criptográfica. 2. Estrategia de Identificación Única Se adopta formalmente el estándar Prefix-ULID / Prefixed UUIDv7. Este enfoque supera las limitaciones de secuencias numéricas simples (que requieren coordinación centralizada y generan cuellos de botella) y de UUIDv4 (que carece de ordenación temporal nativa). Formato Canónico: AUD-EVT-- Ejemplo Representativo: AUD-EVT-01H1BER7S1-9X82B71CA001 4. Clasificación de Severidad Nivel Nombre Propósito y Criterio Arquitectónico 1 TRACE Trazado granular de ejecución interna. Depuración de bajo nivel. 2 DEBUG Información detallada de diagnóstico en entornos de desarrollo. 3 INFO Notificación formal de eventos normales y esperados del ciclo operativo. 4 NOTICE Eventos normales pero significativos que ameritan seguimiento preventivo. 5 WARNING Anomalías o condiciones inesperadas que no impiden la operación. 6 ERROR Fallas que impiden completar una operación específica de un usuario/servicio. 7 CRITICAL Fallas severas que degradan la funcionalidad global de múltiples módulos. 8 FATAL Inoperabilidad total o violación crítica que requiere detención inmediata. 5. Modelo de Actores Tipos de actores reconocidos por el sistema (actor_type): USER: Usuario humano autenticado. ADMINISTRATOR: Usuario con privilegios de gestión de infraestructura o roles. INVESTIGATOR: Perfil operativo de dominio en expedientes e investigaciones. INTERNAL_SERVICE: Microservicio propio del ecosistema CIIS OS. API_CLIENT: Consumidor externo autenticado mediante claves API o tokens. SYSTEM: El núcleo runtime del sistema operativo CIIS OS. CIISMATRIA_ENGINE: Motor determinista de cálculo y reducción numérica. AUTOMATED_PROCESS: Tareas asíncronas o workers internos. SCHEDULED_JOB: Tareas cronometradas o cron jobs periódicos. 6. Objetos Auditables Entidades estandarizadas sobre las cuales se ejecutan acciones (target_type): DOSSIER — Expediente administrativo o técnico. INVESTIGATION — Proceso de investigación activo o archivado. DOCUMENT — Documento de texto, acta, constancia o anexo digital. FILE — Artefacto binario almacenado (imágenes, archivos adjuntos). PIC_PROTOCOL — Especificación o protocolo técnico del programa de ingeniería. CONFIGURATION — Parámetro, variable global o flag del sistema. USER_IDENTITY — Registro de usuario, credenciales o perfil. ROLE_PERMISSION — Esquema de autorización RBAC/ABAC. DATABASE_SCHEMA — Estructura física o lógica de persistencia. CIISMATRIA_MATRIX — Matriz o regla del motor numérico CIISMATRÍA. AUDIT_LOG — Libro unificado o cadena de registros de auditoría. REPORT — Salida estructurada de información o analítica. 7. Reglas Institucionales de Auditoría Inalterabilidad Estricta: Ningún evento registrado podrá ser eliminado o modificado. Sustitución Mediante Compensación: Toda corrección genera un nuevo evento compensatorio o con deltas de cambio. Sello Temporal UTC ISO-8601: El campo timestamp se expresa obligatoriamente en UTC con precisión a milisegundos (YYYY-MM-DDTHH:mm:ss.sssZ). Identificación Universal: Obligatoriedad de event_id basado en Prefix-ULID / UUIDv7. Categorización Obligatoria: Pertenencia estricta a una categoría válida de la taxonomía. Encadenamiento Criptográfico: Todo evento incluye el previous_hash del registro anterior en la secuencia. Serialización Canónica Determinista: Ordenamiento alfabético estricto de claves antes del cálculo de firma/hash. 9. Matriz de Riesgos de Arquitectura y Mitigación ID Riesgo Riesgo Arquitectónico Impacto Estrategia de Mitigación R-01 Crecimiento masivo de almacenamiento por alto volumen de eventos. Alto Particionamiento por rangos temporales y archivado comprimido de logs antiguos. R-02 Manipulación maliciosa de eventos en el almacenamiento. Crítico Implementación de Hash Chaining (Merkle Tree conceptual). R-03 Latencia en transacciones operativas por generación de auditoría. Medio Procesamiento asíncrono con patrón Outbox/Buffer. R-04 Incompatibilidad de esquemas entre módulos. Medio Inclusión obligatoria de schema_version y validación estricta con JSON Schema. 10. Dictamen de Aprobación Institucional Por la presente, la especificación técnica PIC-140-001 (Versión 1.0) — Arquitectura del Motor de Auditoría y Trazabilidad Transversal queda oficialmente **APROBADA Y RATIFICADA** como estándar obligatorio para la arquitectura de software del proyecto **CIIS OS**. Todos los módulos desarrollados o integrados al ecosistema CIIS OS deberán cumplir de manera estricta con las estructuras, validaciones y contratos descritos en este estándar a partir de la fecha de expedición.
